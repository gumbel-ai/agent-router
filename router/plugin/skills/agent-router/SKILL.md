# Agent Router

Monitoring shows every open Router task and up to 100 native observations per page; use `router status --native-offset 100` for the next native page or look up a native ID directly. Native records hold lifecycle metadata only: no transcripts, assistant output, file lists, token usage, or cost. Router cost/usage/time totals cover Router-launched children, include recorded attempts, and exclude parent review waits.

The structured observation-only commands are `router snapshot --json`, `router fleet status --json`, `router fleet capacity --json`, and `router fleet host NAME --json`. They expose local or fleet host identity, sessions, agents, Router-dispatched tasks (lifecycle only), and capacity without granting control. Fleet capacity is evidence, not scheduling authority: do not infer permission to dispatch work, modify reservations, or control a remote process from an `available` state. Missing or stale evidence stays `unknown` or `offline`. For a long-running command whose progress the user wants visible, run it as `router run --label NAME -- command args`; Router records its completion evidence but never stops it.

Delegate only when the user requests it. Do not replace a requested executor or model. Router supports OpenCode, Codex, and Claude Code child executors; unsupported targets fail without fallback. Semantic intent checking is your responsibility, not the router's.

Observation requires project enablement. The operator runs `router setup` to install the CLI, register marketplaces, and install the macOS service; Linux daemon startup is manual with `router daemon start`. The separate `router enable` command installs Claude's plugin at project scope and writes the marker and Claude/Codex project configuration. Commit those project files and start fresh sessions. Codex also requires project trust, an installed plugin cache, and manual hook trust through `/hooks`; Router never grants hook trust. Honor the operator's explicit `CODEX_HOME`, or the client default when unset; do not search or create other homes.

External delegation separately requires `router init` in that project, approving its exact model, setup command, permissions, and limits. Hooks never start the daemon or install dependencies. Never run setup, enable, init, or uninstall on the user's behalf without explicit permission.

The UserPromptSubmit hook supplies `ROUTER_INSTRUCTION_ID`. Use that ID for every delegation from this submission. If it is absent, do not invent it. Check that the operator has started the daemon and configured the repository, model alias, setup command, and executor permissions. OpenCode requires explicit allow/deny permissions in `opencode.json`; Codex requires an operator-approved read-only or workspace-write sandbox in Router configuration. Claude children require an exact Anthropic model and an explicit tools/allow permission profile recorded by `router init --executor claude`. These permission formats are not interchangeable.

Call each mutating operation as one standalone shell command in canonical literal form:

```text
router start --json '<invocation JSON>'
router review --json '<review JSON>'
router cancel --json '<cancel JSON>'
router close --json '<close JSON>'
```

Use single quotes around the JSON. For an apostrophe inside it, use the canonical shell escape `'"'"'`. No variables, substitutions, pipelines, command prefixes, or JSON files. Generate a fresh `request_id` for a new action; replay the identical payload with its existing ID after a transport failure.

Start requires `request_version: "1"`, `request_id`, `instruction_id`, `executor: "opencode"`, `"codex"`, or `"claude"`, the configured `model` alias, `task`, absolute `parent_repo` and `parent_worktree` root paths, and `mode: "write"`. Optional `context` contains arrays `relevant_paths` and `constraints`. The returned task ID means registration, not completion.

Codex aliases use exact `openai/model-id` values. Router passes the model ID to `codex exec --json`, with no approval prompts or unrestricted sandbox bypass. It resumes corrections using the recorded thread ID, never `--last`. Codex native delegation is disabled for Router-launched children. Native Codex sessions are observed through Router's Codex plugin when its hooks are trusted; `router status` reports when they are not. Codex uses its saved CLI login; Router strips provider-key/endpoint overrides from its child environment. Model metadata identifies the configured selection, not an independently reported served model. Token fields retain CLI names: cache reads and writes partition input, and reasoning output is a subset of output. Codex emits cumulative thread counters; Router records per-attempt differences so corrections do not double-count earlier work. `usage_complete: false` means totals contain only reported usage. Cost uses dated standard short-context rates or operator-provided flat rates for input/cache-read/cache-write/output tokens, excludes tool fees and long-context premiums, and remains unknown if required usage or exact pricing is unavailable. A zero exit code without a completed turn and a matching thread ID observed during that attempt is not successful execution.

Claude aliases use exact `anthropic/claude-family-version` IDs. `router init --executor claude` records explicit `tools` and `allow` permission lists; the child uses `dontAsk` and cannot request additional approval. Router checks CLI 2.1.303+ through an owned version phase for each new attempt, binds inspection and execution to one resolved executable, and resumes parent-requested corrections with the recorded native UUID. Its safe-mode child loads no custom hooks, plugins, or MCP servers; managed policy still applies. Different main-model/session evidence or a missing successful result fails without fallback. Tokens come from bounded cumulative per-model result counters; cost is the native aggregate CLI estimate. Prior-attempt deltas prevent double counting, and missing, malformed, overflowed or discontinuous accounting stays incomplete.

Inspect a task with `router status <task_id> --json`. Use `router status --filter needs_decision --json` when you need to act. Do not watch by repeatedly polling from model turns; a person can run `router status --watch` without consuming model context.

The status view includes native Claude subagents as `control_mode: "observe"` alongside Router-launched children as `control_mode: "control"`. Native agents remain Claude-managed: never review, cancel, or close their `native-` IDs through Router. A native `stopped` observation is not evidence of successful work; stale or missing lifecycle evidence is `unknown`. Quiet agents are not assumed dead. Task descriptions and activity are summaries, not complete transcripts or proof of file ownership. Native observations carry the model reported by the host but no token usage or cost; those belong to Langfuse. Router-launched children report usage and API-equivalent cost estimates, not subscription charges or invoices; unknown rates or token details stay unknown. Additional hosts must preserve the same rule: native subagents for observation, Router-launched children for lifecycle control.

When `awaiting_review`, inspect the recorded patch, child files, and test/output artifacts. Review JSON contains `task_id`, `request_id`, `expected_attempt` (the current `attempts` count), and `outcome: "accepted"` or `"rejected"`. Rejection also requires actionable `feedback`; one correction uses the same worktree, session, and resolved model. Limits cannot be changed through task inputs. Process completion does not establish code quality.

Acceptance does not apply code. In the parent worktree, run `git apply --check <recorded-patch>` followed by plain `git apply <recorded-patch>`. If context has changed and the check fails, stop and preserve the child's work for reconciliation. Do not use `--3way`, `--reject`, or merge the child branch. Empty patches need no application.

After integration, close with `task_id`, `request_id`, and `disposition: "integrated"`. For final rejection use `"discarded"`. Close removes the dirty child worktree, branch, and task refs by default. Set `keep_artifacts: true` to retain them. Inspect `cleanup_pending` and `cleanup_error`; replay the same close request to retry failed cleanup. Closed tasks with pending cleanup remain visible; failed cleanup appears in `needs_decision` and does not block maintenance. Queued or running cleanup still blocks it. Daemon startup resumes interrupted, previously requested cleanup only when no failure was recorded; failed cleanup still needs an explicit replay. Cleanup metadata applies only to Router-controlled work; native cleanup belongs to the host.

Cancel JSON contains `task_id` and `request_id`. Wait for verified `cancelled`; uncertain execution remains `interrupted` and cannot be closed. Use cancel to establish stopped execution after an interruption; never launch a replacement while old work may still run.

Cancellation of a Codex or Claude child first interrupts its harness so foreground commands in separate process groups can shut down. Abrupt termination or missing shutdown evidence stays `interrupted` with `shutdown_unconfirmed: true`; a dead CLI alone does not prove its commands stopped. Repeating cancel cannot clear that uncertainty. Preserve the worktree and request operator inspection; do not close or replace the task. After inspecting and stopping all remaining commands, a human can stop the daemon and run interactive `router recover TASK_ID --reason 'inspection details'`, then restart it. Recovery releases the slot, preserves the original uncertainty and artifacts, and records an operator acknowledgement. Never invoke recovery yourself; it is not an agent-facing task operation.

Failed work remains inspectable. You may explicitly accept its artifacts for salvage only when execution is verified stopped and a current final tree exists. Its failed execution outcome and reason remain recorded. Do not retry failed infrastructure in the same task. Neither executor produces the structured blocker outcome in this version.

Worktrees and dependency environments protect the parent checkout during normal execution. They are not a sandbox: OpenCode and Claude children have the host user's filesystem, credentials, and network access subject to their permission profile. Codex commands run in the approved Codex sandbox. Dependency setup runs outside that sandbox and must be operator-approved.
